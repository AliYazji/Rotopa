# Rotopa

إعادة بناء نظام المحاسبة والضيافة (`miles2023` / Retaj) على Supabase — ويب أولاً، ثم تطبيق جوال يشارك نفس الـ API.

خارطة الوحدات والمراحل: انظر [`docs/`](docs/) و[خارطة البناء المنشورة](https://claude.ai/code/artifact/18eab235-34d3-4859-b9a9-bbd369d80c57).

## التقنيات

| الطبقة | الأداة |
|---|---|
| قاعدة البيانات | Supabase — PostgreSQL 15، RLS، Auth |
| الواجهة البرمجية | PostgREST + دوال RPC للمنطق المحاسبي |
| الويب | React + Vite + TypeScript (RTL) — نشر على Cloudflare Pages |
| الجوال (لاحقاً) | React Native + Expo |
| الترحيل | Node/TypeScript ETL من SQL Server |

## البنية

```
supabase/
  migrations/     ← مخطط قاعدة البيانات (مرقّم زمنياً، يُطبَّق بالترتيب)
  tests/          ← اختبارات SQL: تُطبّق كل الهجرات على قاعدة مؤقتة ثم تتحقق
etl/              ← نقل البيانات من النسخة الاحتياطية miles2023
web/              ← تطبيق الويب (React + Vite، ينشر على Cloudflare Pages)
docs/             ← نموذج البيانات وقرارات التصميم والنشر
analysis/         ← مخرجات تحليل النظام القديم (محلي، خارج git)
```

## الويب — ما أُنجز

هيكل التطبيق + المصادقة (Supabase Auth) + إنشاء المؤسسة، وشاشات:
ميزان المراجعة، دليل الحسابات (شجرة)،
**العملاء / الموردون / الموظفون** (سجل واحد مشترك — نفس الطرف ممكن يكون أكتر من دور — بثلاث
قوائم منفصلة لأنه هيك بيفكر المحاسب؛ كل قائمة فيها بحث + طرف جديد بحساب يُنشأ تلقائياً + كشف حساب)،
القيود (قائمة + قيد جديد)، السندات (قبض/صرف، متعدد الأسطر، مع ترحيل وإلغاء)،
الشيكات (وارد/صادر، إيداع/تحصيل/ارتداد/إلغاء/تجيير)، العملات.

```bash
cd web && cp .env.example .env   # املأ VITE_SUPABASE_*
npm install && npm run dev
```

النشر: [`docs/deployment.md`](docs/deployment.md).

### الضمانات المفروضة في قاعدة البيانات (لا في الواجهة)

- **العزل**: كل جدول عليه RLS؛ لا صف يُرى أو يُكتب إلا عبر عضوية + صلاحية.
- **التوازن**: القيد المرحّل ≥ سطرين ومجموع المدين = الدائن (بعملة الأساس) وإلا يُرفض.
- **السطر**: مدين أو دائن، لا الاثنين، لا صفر. المبالغ `numeric(19,4)` لا `float`.
- **العملات**: كل سطر يحمل سعر الصرف المستخدم؛ `مبلغ الأساس = المبلغ الأجنبي × السعر` مُتحقَّق.
- **الشجرة**: لا حركة على حساب أب؛ لا دورات؛ المسار والعمق يُصانان تلقائياً.
- **الفترات**: لا ترحيل في فترة غير مفتوحة.
- **عدم القابلية للتغيير**: القيد المرحّل ثابت؛ التصحيح بقيد عكسي (`void_journal_entry`).
- **التدقيق**: كل تغيير على جدول رئيسي يُسجَّل في `audit_log`.

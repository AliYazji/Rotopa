# Rotopa

إعادة بناء نظام المحاسبة والضيافة (`miles2023` / Retaj) على Supabase — ويب أولاً، ثم تطبيق جوال يشارك نفس الـ API.

خارطة الوحدات والمراحل: انظر [`docs/`](docs/) و[خارطة البناء المنشورة](https://claude.ai/code/artifact/18eab235-34d3-4859-b9a9-bbd369d80c57).
حالة حقيقية لما هو جاهز للإنتاج وما لا يزال ناقصاً: [`docs/pre-launch-checklist.md`](docs/pre-launch-checklist.md).

## التقنيات

| الطبقة | الأداة |
|---|---|
| قاعدة البيانات | Supabase — PostgreSQL 15، RLS، Auth |
| الواجهة البرمجية | PostgREST + دوال RPC للمنطق المحاسبي |
| الويب | React + Vite + TypeScript (RTL) — نشر على Cloudflare Pages |
| الجوال (لاحقاً) | React Native + Expo |
| الترحيل | Node/TypeScript ETL من SQL Server |

## البنية

```
supabase/
  migrations/     ← مخطط قاعدة البيانات (مرقّم زمنياً، يُطبَّق بالترتيب)
  tests/          ← اختبارات SQL: تُطبّق كل الهجرات على قاعدة مؤقتة ثم تتحقق
etl/              ← نقل البيانات من النسخة الاحتياطية miles2023
web/              ← تطبيق الويب (React + Vite، ينشر على Cloudflare Pages)
docs/             ← نموذج البيانات وقرارات التصميم والنشر
analysis/         ← مخرجات تحليل النظام القديم (محلي، خارج git)
```

## الويب — ما أُنجز

هيكل التطبيق + المصادقة (Supabase Auth) + إنشاء المؤسسة، وشاشات:
ميزان المراجعة، **قائمة الدخل** و**الميزانية العمومية** (مجمّعة حسب تصنيف الحساب، بتحذير احتياطي
لو في حسابات برصيد بلا تصنيف — الفجوة الحقيقية يلي كانت موجودة هون انحلّت بخطوة ETL جديدة تصنّف
كل حساب من شجرة الحسابات نفسها بمنطق محاسبي، راجع `etl/README.md`)،
**دليل الحسابات** (شجرة، حساب جديد، وصفحة لكل حساب فيها تعديل + كشف الحساب)،
**العملاء / الموردون / الموظفون** (سجل واحد مشترك — نفس الطرف ممكن يكون أكتر من دور — بثلاث
قوائم منفصلة لأنه هيك بيفكر المحاسب؛ كل قائمة فيها بحث + طرف جديد بحساب يُنشأ تلقائياً + صفحة
لكل طرف فيها **تعديل** + كشف حساب)،
القيود، السندات (قبض/صرف، متعدد الأسطر)،
الشيكات (وارد/صادر، إيداع/تحصيل/ارتداد/إلغاء/تجيير)، **الأصناف** (بحث فوري على آلاف
الأصناف، صنف جديد، صفحة كل صنف فيها **تعديل** + الرصيد لكل مستودع وحركته)، **حركات المخزون**
(رصيد افتتاحي/إضافة/صرف/تحويل، بتكلفة متوسط مرجّح وترحيل محاسبي اختياري)، **فواتير المبيعات**
(فاتورة آجلة أو نقدية، بحث فوري عن الصنف يوري المتوفر بالمستودع قبل ما تحاول، ترحيل يحرّك
المخزون والقيد المحاسبي بقيد واحد، ضريبة 16% محسوبة تلقائياً وتظهر بالإجمالي قبل الترحيل)،
**الكاشير** (`/pos` — بيع سريع بلمسات: بحث/تصنيف عن الصنف بشبكة، سلة بكمية قابلة للتعديل،
دفع **فوري** لصندوق مبيعات مُختار (بزبون نقدي عام يُنشأ مرة وحدة تلقائياً) أو **آجل** لزبون
محدد — نفس محرك فاتورة المبيعات تماماً من تحت، غير واجهة إدخال بس)، **فواتير المشتريات**
(آجلة أو نقدية، تكلفة سطر الفاتورة هي تكلفة الوارد للمخزون مباشرة —
بلا حساب وسيط، نفس حساب الضريبة تلقائياً)، **الأصول الثابتة** (تسجيل يرحّل فوراً،
ترحيل إهلاك فردي أو دفعة لكل الأصول النشطة حتى تاريخ معيّن، استبعاد بربح أو خسارة)، **كشوف
الرواتب** (كل موظف بسطر بإضافاته واستقطاعاته الخاصة، قيد واحد مجمّع)، **الفندقة** (غرف وأنواعها،
حجز جديد برفض تلقائي لو الغرفة محجوزة بنفس الفترة، وصول/مغادرة، ترحيل ليلة فردي أو دفعة لكل
الحجوزات الواصلة بتاريخ معيّن، سجل ليالٍ مُرحّلة لكل حجز بروابط للقيود)، **المطعم/نقاط البيع**
(منافذ وطاولات، فتح طلب على طاولة يرفض لو الطاولة مشغولة، إضافة أصناف بأي وقت قبل التسوية،
التسوية تختار فوري-لصندوق أو آجل-لزبون تماماً متل الكاشير وبتحوّل الطلب لفاتورة مبيعات حقيقية
مرحّلة، الطاولة بتصير متاحة تلقائياً)، **مرتجعات المبيعات والمشتريات** (مرجع جزئي أو كامل على
فاتورة مرحّلة محددة — يختار المستخدم أي صنف وأي كمية من أصنافها، بسعر وتكلفة الفاتورة الأصلية
نفسها لا رقماً جديداً، برفض تلقائي لو مجموع كل المرجعات المرحّلة على نفس السطر تجاوز ما بيعه/اشتراه
أصلاً — هاد الفرق الجوهري عن **إلغاء** الفاتورة كاملة الموجود أصلاً بالوحدتين 10/11)، العملات،
**الفريق** (قائمة الأعضاء بدورهم وفرعهم وحالة تفعيلهم، دعوة عضو جديد بالبريد الإلكتروني، دعوات
معلَّقة قابلة للإلغاء) و**الأدوار والصلاحيات** (الأدوار الثلاثة النظامية للعرض فقط، دور مخصّص
جديد بصلاحياته عبر شبكة اختيار مجمّعة حسب الوحدة)، وإضافة **تسجيل الخروج من كل الأجهزة** و**نسيت
كلمة المرور** لصفحة الدخول، و**الفترات المحاسبية** (إقفال/إعادة فتح كل فترة وكل سنة مالية بترتيبها
الصحيح، مع سجل دائم لكل عملية وسببها)، و**سجل التدقيق** (فلترة حسب الجدول/العملية/المستخدم/معرّف
السجل/التاريخ، عرض الفرق بين القيمة قبل وبعد لكل سطر تعديل، ترقيم صفحات)، و**لوحة تحكم تشغيلية**
حقيقية بدل ميزان المراجعة المعروض كأنه الصفحة الرئيسية (نقد/ذمم/مبيعات ومشتريات الشهر/حالة الفترة/
قائمة بانتظار الإجراء/آخر النشاطات من سجل التدقيق)، **إعدادات المؤسسة** (`/settings` — اسم المؤسسة،
بيانات ترويسة الطباعة)، **طباعة فاتورة المبيعات** (`components/PrintInvoice.tsx` — قابل لإعادة
الاستخدام لأي مستند آخر لاحقاً)، ومؤشر بسيط "بانتظار الإجراء" بالشريط الجانبي (ليس نظام إشعارات
حقيقياً — إعادة استخدام لأرقام اللوحة الرئيسية فقط).

**كل مستند (قيد، سند، حركة مخزون، فاتورة مبيعات، فاتورة مشتريات، مرجع مبيعات، مرجع مشتريات، كشف رواتب) له صفحة تفاصيل بنفس النمط:**
مسودة قابلة للتعديل الكامل أو الترحيل أو الحذف؛ مرحّل ثابت لا يُعدَّل ولا يُحذف —
فقط **إلغاء** بمرجع/حركة عكسية تعيد الحالة (قيد، مخزون، رصيد) وتوثّق السبب؛ وزر
**نسخ لمسودة جديدة** على المرحّل والملغى لتصحيح سريع بدل إعادة الطباعة من الصفر.

```bash
cd web && cp .env.example .env   # املأ VITE_SUPABASE_*
npm install && npm run dev
```

النشر: [`docs/deployment.md`](docs/deployment.md).

### الضمانات المفروضة في قاعدة البيانات (لا في الواجهة)

- **العزل**: كل جدول عليه RLS؛ لا صف يُرى أو يُكتب إلا عبر عضوية + صلاحية.
- **التوازن**: القيد المرحّل ≥ سطرين ومجموع المدين = الدائن (بعملة الأساس) وإلا يُرفض.
- **السطر**: مدين أو دائن، لا الاثنين، لا صفر. المبالغ `numeric(19,4)` لا `float`.
- **العملات**: كل سطر يحمل سعر الصرف المستخدم؛ `مبلغ الأساس = المبلغ الأجنبي × السعر` مُتحقَّق.
- **الشجرة**: لا حركة على حساب أب؛ لا دورات؛ المسار والعمق يُصانان تلقائياً.
- **الفترات**: لا ترحيل في فترة غير مفتوحة.
- **عدم القابلية للتغيير**: القيد المرحّل ثابت؛ التصحيح بقيد عكسي (`void_journal_entry`). وممنوع **حذفه**
  كمان — نفس القاعدة على القيود والسندات والشيكات وحركات المخزون وفواتير المبيعات والمشتريات
  ومرتجعاتهما وكشوف الرواتب؛ المسودات فقط قابلة للحذف. **الأصول الثابتة أصرم**: ما في مسودة أصلاً، فالصف
  ثابت وغير قابل للحذف من لحظة التسجيل — التصحيح باستبعاد وتسجيل نسخة صحيحة، لا بتعديل أو حذف.
- **التدقيق**: كل تغيير على جدول رئيسي يُسجَّل في `audit_log`.
- **المخزون**: لا يقبل صرف أكتر من الرصيد الفعلي؛ تكلفة سطر الصرف تُحسب من المتوسط المرجّح
  وقت الترحيل (مش رقم يُدخله المستخدم)؛ التحويل بين مستودعين يرث تكلفة المصدر دايماً، حتى لو
  أُدخل رقم مختلف بالغلط.

## الاختبارات

```bash
bash supabase/tests/run.sh          # يشغّل قاعدة postgres مؤقتة عبر Docker
# أو مقابل قاعدة قائمة:
PGURL=postgres://... bash supabase/tests/run.sh
```

27 ملف اختبار (`supabase/tests/*.sql`) — كل وحدة على حدة، بالإضافة لـ `270_workflow_e2e.sql` (سيناريو
أعمال متكامل عابر للوحدات). اختبارات إضافية خارج `run.sh` (لا تصلح بصيغة `.sql` وحدها):
- `supabase/tests/concurrency/run.sh` — عمليتان متوازيتان فعلياً على مخزون محدود، يتحقق من عدم البيع
  المزدوج تحت تزامن حقيقي. مُدمج بـ CI.
- `supabase/tests/performance/bulk-posting.sql` — تنبيه انحدار أداء (300 قيد)، ليس معيار قياس.

## النسخ الاحتياطي والاستعادة والمراقبة

```bash
scripts/backup-db.sh                                # نسخة .dump مُختصرة بالمخططات (public/app/auth)
scripts/restore-db.sh backups/rotopa_backup_....dump  # استعادة في مكانها على قاعدة مُهيَّأة أصلاً
```

تفاصيل كاملة (لماذا `--no-privileges` كانت فكرة خاطئة، لماذا الاستعادة لازم تكون على قاعدة مُهجَّرة
أصلاً لا فارغة، توصيات المراقبة، ودليل الاسترداد الطارئ خطوة بخطوة) بـ [`docs/deployment.md`](docs/deployment.md).
تحقّق أسبوعي تلقائي من موثوقية الاستعادة عبر `.github/workflows/backup-verify.yml` — يستعيد نسخة
فعلية **ويُعيد تشغيل كل ملفات الاختبار عليها**.

> ملاحظة: حاوية `supabase_db_rotopa` العاملة محلياً تخص مشروعاً آخر — لا نستخدمها. اختبارات هذا المشروع تعزل نفسها في حاوية `rotopa-pgtest`.
